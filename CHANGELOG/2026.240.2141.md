# 2026.240.2141 — fix: drop the internals plugin stdio github MCP server (the only non-pod-provided one)

## Summary

The `internals` plugin declared an MCP server that no consumer can use:

```yaml
mcp_servers:
  - name: github
    type: stdio
    command: "github-mcp-server"
```

**Why it is wrong, precisely.** This candy declares five `mcp_servers` blocks.
Four are `type: http` pointing at the port the plugin's own pod serves —
`jupyter` :8888, `charly` :18765, `chrome-devtools` :9224, `marimo` :22718.
Those are correct by construction: the plugin ships the box, the box serves MCP,
and a `ConnectionRefused` when no box is running is the expected state, not a
defect.

The `internals` entry is the **only `type: stdio`** one, and `charly-internals`
ships no pod at all — it is contributor tooling. It shells out to
`github-mcp-server`, a third-party binary this candy neither installs nor
declares as a dependency. On any host without that binary the server fails to
start on **every** session. It also duplicates the `gh` CLI that
`/charly-internals:git-workflow` already mandates for exactly these operations
(PRs, issues, workflow runs, file contents, commits, branches).

Found while auditing why `opencharly/opencharly` loaded zero plugin skills
(opencharly/opencharly#30). Once the skills loaded, `plugin:charly-internals:github`
was the one MCP server still failing — the other four had left with the image
plugins the umbrella does not enable.

**Change:** removed the `mcp_servers:` block, and the trailing
`"and the github MCP server"` clause from the plugin `description`, which
advertised the same dead capability into `marketplace.json` and
`internals/.claude-plugin/plugin.json`.

No skill markdown referenced this server, so nothing else needs updating.
The sweep proving it is pasted under **How tested** below.

## Rulebook compliance

- **R1 — RCA before remediation.** The five failing MCP servers were diagnosed
  individually rather than as one bucket; four are correct config and were left
  alone, one is a real defect and is fixed here at its authoritative source.
- **R3 — No duplication.** The removed server duplicated the `gh` CLI the
  git-workflow skill already mandates; one canonical path for GitHub operations

  repos; `fix/` branch, no force-push, no hook bypass, no direct push to `main`.

  above, run on the final committed tree, plus a negative control proving the
