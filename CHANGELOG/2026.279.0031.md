# 2026.279.0031 — feat(marketplace): declare the qdrant and kubevirt families

## Summary of changes

Two fixes in `charly.yml`, both required for the marketplace corpus to accept the
`qdrant`/`kubevirt` families. Two commits, one file, **+11/-0**.

**1. `feat(marketplace): declare the qdrant and kubevirt families` (`5ed785f`)**

The `marketplace:` entity's `families:` map must declare every family a pinned repo's `skill:`
entities use. `charly marketplace generate` fails otherwise, with a precise error:

```
charly marketplace: skill "check-kubevirt" declares family "kubevirt" which the marketplace
entity does not declare (add it to the marketplace `families:` map)
```

Three repos that own `triggers:`-bearing skills were never pinned in the marketplace refs list,
so the emitter never saw them and their skills were **absent from the corpus entirely** — the
generated dispatcher therefore carried no row for any of them:

| Repo | Skill(s) | Family |
|---|---|---|
| `layer-qdrant` | `qdrant` | `qdrant` |
| `plugin-qdrant` | `qdrant-cli` | `qdrant` |
| `plugin-kubevirt` | `kubevirt`, `check-kubevirt`, `kubevirt-operator` | `kubevirt` |

- `kubevirt` — category `kind`, matching its sibling schema-authoring families (`vm`,
  `kubernetes`, `pod`, `local`): the 7th deploy substrate, the VirtualMachine CR lifecycle, the
  out-of-process `kubevirt:` check verb, and the pinned KubeVirt + CDI platform install.
- `qdrant` — category `images`, matching the service families (`ollama`/`openwebui`/`comfyui`):
  the pinned static-musl service candy plus the `charly qdrant` CLI and the `qdrant:` check verb.

**2. `fix(marketplace): restore the version: stamp the loader requires` (`89739a3`)**

`charly box validate` — this repo's own gate — **failed** on the `marketplace:` entity:

```
node "marketplace": plugin kind:marketplace: plugin_input fails
#MarketplaceInput: #MarketplaceInput.version: incomplete value =~"^[0-9]+[.][0-9]+[.][0-9]+$"
```

Root cause, established by `git log -S 'version:'` (output pasted in block 3): the org-wide
cutover `54f8f4a` (*"chore(schema): drop the retired config version: stamp"*) removed **three**
`version:` lines from this file. The entity field is still **required** by the schema the host
validates against (`#MarketplaceInput.version`) and by the core `#Marketplace`, and the generator
consumes it (`emit_marketplace.go`: `m.Version = ks.Marketplace.Version`). The stamp removal
over-reached for this entity. This is the same class the umbrella already cured once by restoring
the stamp: **opencharly/opencharly#309**.

**Closes / relates to:** relates to opencharly/opencharly#382 (the R0 coverage cutover).

**Breaking change + rollback:** none — additive map entries plus a restored required field.
Rollback is a revert.
