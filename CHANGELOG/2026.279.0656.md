# 2026.279.0656 — fix(marketplace): drop the version: stamp the design retired

## Summary of changes

The marketplace versions by commit SHA — `marketplace/README.md` states it plainly:

> *"No `version` fields anywhere: plugins version by the marketplace commit SHA, so every corpus
> update is picked up on `/plugin marketplace update`."*

The org-wide cutover (*"drop the retired config version: stamp"*) removed the stamp from every
`marketplace:` entity to implement exactly that. **An earlier PR on this branch (#12) restored the
stamp** to make `charly box validate` pass. That was the wrong direction: it re-introduced a field
the design deliberately removed, and it made the generator stamp `version` onto
`.claude-plugin/marketplace.json` **and all 346 `.well-known/skills/index.json` entries** —
defeating commit-SHA versioning.

The real defect was that the cutover **never updated the schema**, so `#MarketplaceInput.version`
stayed required. That is now fixed at the root, in the producer repos:

| Leg | Change | State |
|---|---|---|
| `opencharly/plugin-harness-kind#7` | `#MarketplaceInput.version?` (the loader's gate) | **merged** |
| `opencharly/spec#200` | `#Marketplace.version?` (the core contract) | **merged** |

With the schema optional, the stamp is unnecessary. **One file:** remove the `version:` line from
the `marketplace:` entity.

**Closes / relates to:** unblocks opencharly/marketplace#422.

**Breaking change + rollback:** none for a consumer on the *fixed* schema — a required field
became optional, so every config that validated before still validates, and a version-less entity
now validates too. **Ordering:** the fix reaches the shipping binary through
**opencharly/charly#813**, which bumps `plugin-harness-kind` + `spec` to the optional-version tags.
Until that pin advance lands, a build pinned to the OLD plugin rejects a version-less entity
(block 1) — which is precisely why the pin advance is part of this cutover, not a follow-up.
Rollback is a revert.
