# 2026.319.1500 — feat(marketplace): register the qwen3-tts skill family

## Summary

`pod-qwen3-tts` declares a skill in its own family:

```yaml
qwen3-tts-skill:
    skill:
        name: qwen3-tts
        family: qwen3-tts
        owner: qwen3-tts
```

and the marketplace generator refuses any family the `marketplace:` entity does not list:

```
charly marketplace: skill "qwen3-tts" declares family "qwen3-tts" which the marketplace entity does not declare (add it to the marketplace `families:` map)
```

That aborts the whole corpus build (`opencharly/marketplace#613`) — measured after two other
corpus blockers were cleared this session.

| file | change |
|---|---|
| `charly.yml` | the `qwen3-tts:` entry in the `marketplace:` entity's `families:` map, between `qdrant:` and `review:` |

The shape is copied from its siblings (`qdrant`, `strata`, `comfyui`, `immich`) — one
per-product family whose skills cover one service family — and the description is taken from the
skill's own frontmatter, not invented:

> The Qwen3-TTS speech service candy and pod: the OpenAI-compatible speech API (POST
> /v1/audio/speech, GET /v1/audio/voices) that Open WebUI's `openai` TTS engine calls, served over
> the upstream qwen-tts python API by a charly-owned shim.
